# 背景

`scanly/train/` 下 YOLO 检测（`train.py`）、RT-DETRv2（`train_rtdetrv2.py`）、OBB（`train_obb.py`）各自在 `__main__` 里写死数据路径、类别列表与训练超参。YOLO 与 RT-DETRv2 本应共用同一批源数据与类别过滤，却在两个入口重复维护，改数据易漏改一侧。insect 工程已用「公共数据配置 + 各入口训练配置」拆开，scanly 需要对齐该方式。

# 目标

1. 将数据源、类别、划分等公共项抽到独立配置目录，YOLO / RT-DETRv2 / OBB 共用。
2. 将各入口的模型路径、训练超参、staging 输出等留在各自训练配置中，与数据配置解耦。
3. 入口脚本默认读配置文件；`__main__` 仅保留配置路径与少量运行开关（如只验证、续训），不强制 argparse。

# 要求

## 功能性要求

1. **公共数据配置**：目录 `scanly/train/train_detect_cfg/`，至少含 `data_cfg.json` 与加载合并逻辑。覆盖：源数据根（YOLO 导出或等价）、可选扁平 VOC 路径、`train_classes`、划分比例与种子、空标签与拷贝/软链开关。改数据路径或类别只改本目录（入口 JSON 可覆盖同名键）。
2. **入口训练配置**：
   - YOLO 检测：`scanly/train/train_detect_yolo/train_config.json`
   - RT-DETRv2：`scanly/train/train_detect_core/train_config.json`
   - OBB：`scanly/train/train_detect_obb/train_config.json`
   各文件写本入口的 staging/`output_dir`、跳过准备、模型/yaml/预训练、训练超参段 `train` 等；不得再在脚本里复制一份默认数据列表作为真源。
3. **合并规则**：公共 `data_cfg.json` 为底，入口 `train_config.json` 覆盖同名键；`train` 段逐键覆盖。相对路径：公共数据路径相对 `train_detect_cfg/`；入口覆盖后的路径相对该入口配置所在目录。
4. **入口行为**：`train.py` / `train_rtdetrv2.py` / `train_obb.py` 默认加载对应 `train_config.json` 并与公共配置合并后执行；语义与解耦前一致（含 `VOC` 优先、`SKIP_PREPARE`、`SINGLE_CLS` 等）。
5. **验证脚本**：`test.py` / `test_rtdetrv2.py` 可继续用变量入口，但数据目录与 imgsz/batch 等须能与对应训练配置对齐（读配置或注明与配置同值）；不得再维护第三份独立数据真源。

## 非功能性要求

1. 不改变数据准备与训练算法行为，仅改配置落点与加载方式。
2. 不引用 scanly 以外工程目录的配置加载实现（可对照 insect 模式自写）。
