# 开发设计目录（02-dr）

## 目录用途

存放 scanly（板材封边缺陷智能检测）的开发设计文档，作为需求到实现之间的设计真源。本阶段以视觉算法与软件融合设计为主。

## 文档范围

**允许放入：**

- 系统/模块架构设计
- 算法流水线、接口契约、数据模型
- 与现有客户软件/硬件的融合方案

**不应放入：**

- 原始客户资料原文（放在 `doc/00-客户资料/`）
- 测试用例与测试设计（后续放入 `doc/03-tr/`）
- 运维发布说明（后续放入 `doc/99-ops/`）

## 编辑规则

- 子目录使用 `主题名` 或 `编号 模块名` 组织（如 `视觉算法/`、`缺陷推理/`、`缺陷训练/`）
- 设计文档建议包含「关联文档」章节，引用客户资料或后续 OR 路径
- 设计变更直接改对应章节，不堆叠变更日志
- 单文档建议不超过 300 行；过长则拆分子文档并在父文档引用

## 协作约定

| 相邻目录 | 关系 |
|:---|:---|
| `doc/00-客户资料/` | 输入真源；设计引用其路径，不修改其内容 |
| `doc/01-or/` | 正式需求；本目录设计须追溯到对应 OR |
| `doc/03-tr/` | 修改本目录设计时，须同步检查测试设计是否需更新 |
| `defects/` | 标注数据、转换工具与 `defects/predict/` 推理服务 |
| `scanly/train/` | YOLO / RT-DETRv2 检测训练；设计见 `02-dr/缺陷训练/` |

优先级：客户资料中的产品能力与现场软件契约 ≥ OR 要求 > 本目录架构决策 > 实现细节。
