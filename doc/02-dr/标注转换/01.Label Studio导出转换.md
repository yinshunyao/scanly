# 功能设计

## 输入形态

1. **目录模式**：在输入目录下收集 `*.json`（`recursive=True` 默认开启，含全部子目录）。每个 JSON 可为单任务、任务数组，或按图命名的 `xxx.jpg.json`。
2. **单文件模式**：一个 JSON 数组，元素为 Label Studio 任务（含 `data`、`annotations`）。
3. **图像定位**：输入目录即图像根；优先在标注 JSON 同目录查找，再在输入树下按文件名匹配。LS 上传名中日期与时间之间的 `_` 可回退匹配本地空格文件名。

任务字段约定：

| 字段 | 用途 |
|:---|:---|
| `data.image` | 图像 URI / 路径；basename 作回退文件名（可去掉 LS 上传 UUID 前缀 `xxxxxxxx-`） |
| `annotations[0].result[]` | 取第一条 annotation 的 result；忽略 predictions |
| `result[].type` | 仅处理 `rectanglelabels` |
| `result[].value` | `x,y,width,height` 为相对百分比；`rectanglelabels[0]` 为类别名 |
| `result[].original_width/height` | 无本地图像时的尺寸回退 |

## 坐标换算

百分比 → 像素：

```
x1 = x/100 * W
y1 = y/100 * H
x2 = (x+width)/100 * W
y2 = (y+height)/100 * H
```

再走与 `convert.py` 相同的裁剪与 YOLO / VOC 写出逻辑。`rotation != 0` 时记录警告并仍按轴对齐框处理（当前样本旋转均为 0）。

## 类别映射

1. 若配置了 `Categories.json`：按其中 `id` 升序建立 `name → id`；未知类别名记入 skipped 并告警。
2. 否则：扫描全部任务收集标签名，按名称排序后从 0 编号，并写出 `data.yaml` / `predefined_classes.txt`。

## 输出开关

`__main__` 仅配置：

| 变量 | 含义 |
|:---|:---|
| `INPUT_DIR` | 输入根（JSON + 图像，默认可递归） |
| `OUTPUT_DIR` | 输出根 |
| `OUTPUT_FORMAT` | `yolo` 或 `voc` |
| `RECURSIVE` | 是否递归子目录，默认 `True` |

YOLO 布局与现有 `convert.py` 一致：

```
OUTPUT_DIR/
├── data.yaml
├── images/train/
└── labels/train/
```

VOC 布局：

```
OUTPUT_DIR/
├── JPEGImages/
├── Annotations/
└── predefined_classes.txt
```

## 入口

`convert_from_ls.py` 提供 `convert_from_ls(...)`；`__main__` 用模块内变量配置，便于 IDE 直接运行（不强制 CLI）。

# 约束与边界

- 不解析多边形、刷子、关键点等非 `rectanglelabels` 类型。
- 不自动从 Label Studio 服务器拉图；图像须已落在输入目录树内。
- 入口不再要求单独配置图像目录；JSON 与图应在同一输入树下（可分属不同子目录）。
- 不修改 `doc/00-客户资料/` 下导出样例。
