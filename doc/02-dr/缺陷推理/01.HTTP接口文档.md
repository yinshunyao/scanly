# 板材封边缺陷推理 HTTP 接口（v1）

基地址默认 `http://127.0.0.1:37870`（Python + Gradio）。Go 产线服务默认 `http://127.0.0.1:37871`，**路径版** JSON 字段相同、无 Gradio，见 `scanly/defects/predict_go/README.md`。路径接口 `Content-Type: application/json; charset=utf-8`。内网本机、无鉴权。

**边端主路径**：图像传本机绝对路径（`POST /v1/predict`）。**跨机/调试**：可用 `POST /v1/predict/upload` 以 multipart 上传图像（Python 服务实现；Go 本迭代可不实现）。

成功与业务失败均为 **HTTP 200**；用 `code` 区分。`code=0` 成功，非 0 失败（常用 `500`）。`GET /docs` 中 200 示例为完整 JSON（`PredictResponse`），不是 `"string"`。

```json
{"code": 500, "msg": "读取图片异常"}
```

| 方法 | 路径 | 说明 |
|:---|:---|:---|
| GET | `/health/ready` | 就绪检查。未就绪时 HTTP **503** |
| POST | `/v1/predict` | 按相机推理（本机路径，推荐产线） |
| POST | `/v1/predict/upload` | 按相机推理（multipart 上传图像） |
| POST | `/scanly_predict` | 与 `/v1/predict` 相同 |
| GET | `/v1/labels` | 类别对照表 |
| GET | `/v1/scheme` | 查询当前方案（缺陷启停 + 判定参数） |
| PUT / POST | `/v1/scheme` | **配置**当前方案；默认写回 `scheme.json` |
| GET | `/docs` | Swagger（调试） |
| — | `/` | Gradio 调试页，不是产线接口 |

## 1. 预测 `POST /v1/predict`（`POST /scanly_predict` 相同）

Body 可为**相机数组**（兼容旧客户端），或包一层对象（推荐，便于带 `infer_type` / 方案 / 标定）。不使用 query。

相机数组：

```json
[
  {"camera": "ch1", "images": ["C:/data/c1_pic1.bmp", "C:/data/c1_pic2.bmp"]},
  {"camera": "ch2", "images": ["C:/data/c2_pic1.bmp"]}
]
```

对象包一层（相机数组放在 `cameras`）：

```json
{
  "infer_type": "obb",
  "cameras": [{"camera": "ch1", "images": ["C:/data/c1_pic1.bmp"]}],
  "laminating": false,
  "calib": {"mm_per_px": 0.03},
  "scheme": {"defects": [{"name": "Tackless", "confidence": 0.45}]}
}
```

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| `[].camera` / `cameras[].camera` | string | 是 | 相机号，由边端定义（如 `ch1`） |
| `[].images` / `cameras[].images` | string[] | 是 | 本机图像绝对路径，顺序即该路图序；无图传 `[]` |
| `infer_type` | string | 否 | `detect`（轴对齐）或 `obb`（旋转框）。仅对象包一层时生效；缺省用 `predict.json` 的 `infer_type`，**配置未写时默认 `obb`** |
| `board_id` / `scheme_name` | string | 否 | 板材 ID / 方案名回显 |
| `laminating` / `calib` / `scheme` | — | 否 | 覆膜、标定、本次方案覆盖（不写盘） |

`infer_type=obb` 但未加载 OBB 权重：`code=500`，`msg=OBB模型未加载`。检测同理为 `检测模型未加载`。

### 成功响应

`results` 与入参相机顺序一致；每个相机的 `defects` 是**二维数组**，`defects[i]` 对应 `images[i]` 的缺陷列表（无缺陷为 `[]`）。顶层回显本次实际使用的 `infer_type`。

```json
{
  "code": 0,
  "msg": "ok",
  "engine": "scanly-defects-v1",
  "infer_type": "obb",
  "board_ok": false,
  "elapsed_ms": 82.1,
  "results": [
    {
      "camera": "ch1",
      "defects": [
        [
          {
            "name": "Shorter",
            "cn_name": "短带",
            "score": 0.86,
            "infer_type": "obb",
            "location": {"left": 120, "top": 40, "width": 180, "height": 24},
            "obb": {
              "points": [[120, 42], [298, 40], [300, 62], [122, 64]],
              "cx": 210.0,
              "cy": 52.0,
              "width": 180.2,
              "height": 22.1,
              "angle": 0.02
            },
            "height_mm": 0.66,
            "length_mm": 5.41,
            "area_mm2": 3.57,
            "ng": true,
            "need_label": true,
            "need_discharge": false
          }
        ],
        []
      ]
    }
  ]
}
```

| 字段 | 说明 |
|:---|:---|
| `infer_type` | 本次推理类型，与请求/配置一致 |
| `board_ok` | 全部图均无 `ng=true` 时为 `true` |
| `location` | 轴对齐外接框像素 `left/top/width/height`（detect 与 obb 都返回，便于兼容） |
| `obb` | 统一输出：四点 `points`（像素）、`cx/cy/width/height/angle`（弧度）。detect 时为矩形四顶点且 `angle=0` |
| `height_mm` / `length_mm` | 按 `obb.width/height` 的短边/长边 × `mm_per_px`（detect 的 bbox 已转为 angle=0 的 OBB） |
| `ng` / `need_label` / `need_discharge` | 达到该类 NG / 贴标 / 排出规则 |

边端：`board_ok==false` 或任一条 `ng==true` 视为 NG。`obb` 未出现时按 `location` 画水平框即可。

### 失败 `msg`（`code=500`）

`请求body必须是JSON` / `请求body必须包含相机与图片路径` / `camera不能为空` / `images必须是数组` / `图片路径不能为空` / `不支持的推理类型` / `检测模型未加载` / `OBB模型未加载` / `推理服务尚未就绪，请稍后重试` / `读取图片异常`

`GET /health/ready` 未就绪：`{"ready":false,"model_loaded":false,"infer_type":"obb","msg":"模型未加载"}`，HTTP 503。就绪时带 `detect_loaded` / `obb_loaded`。

## 1.1 上传预测 `POST /v1/predict/upload`

`Content-Type: multipart/form-data`。落盘为临时文件后走与 `/v1/predict` 相同的推理与判定；**响应 JSON 完全一致**（含 `results[].defects[][]`）。不改变路径接口。

| 表单字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| `files` | file[] | 是 | 一张或多张图像；**顺序**与 `meta.cameras[].count` 对齐 |
| `meta` | string (JSON) | 否 | 对象：可含 `cameras`、`infer_type`、`board_id`、`laminating`、`mm_per_px`/`calib`、`scheme`/`scheme_name` |
| `camera` | string | 否 | 未写 `meta.cameras` 时：全部 `files` 归该相机；都缺省则相机号为 `ch1` |
| `infer_type` | string | 否 | 覆盖 `meta` / 配置；`detect` 或 `obb` |
| `laminating` | string/bool | 否 | 覆膜；表单常写 `true`/`false` |
| `mm_per_px` | number | 否 | 标定；也可只放在 `meta.calib` |
| `board_id` | string | 否 | 板材 ID |

`meta.cameras` 示例（多相机多图）：

```json
{
  "infer_type": "obb",
  "cameras": [
    {"camera": "ch1", "count": 2},
    {"camera": "ch2", "count": 1}
  ],
  "laminating": false,
  "calib": {"mm_per_px": 0.03}
}
```

此时须上传 **3** 个 `files`：前 2 张归 `ch1`，第 3 张归 `ch2`。`sum(count)` 必须等于 `files` 个数。

单路简写（可不传 `meta`）：

```bash
curl -s -X POST http://127.0.0.1:37870/v1/predict/upload \
  -F 'camera=ch1' \
  -F 'infer_type=obb' \
  -F 'files=@/data/edge/a.bmp'
```

多相机：

```bash
curl -s -X POST http://127.0.0.1:37870/v1/predict/upload \
  -F 'meta={"cameras":[{"camera":"ch1","count":2},{"camera":"ch2","count":1}],"infer_type":"obb"}' \
  -F 'files=@/data/c1_1.bmp' \
  -F 'files=@/data/c1_2.bmp' \
  -F 'files=@/data/c2_1.bmp'
```

### 失败 `msg`（上传专用，`code=500`）

`必须上传files` / `meta必须是JSON对象` / `meta不是合法JSON` / `meta.cameras必须是非空数组` / `camera不能为空` / `count必须为正整数` / `上传文件数与cameras.count合计不一致` / `上传文件为空` / 以及与路径接口相同的模型未加载、读图解码失败等。

## 2. 类别 `GET /v1/labels`

```json
{
  "code": 0,
  "engine": "scanly-defects-v1",
  "items": [
    {"name": "GlueSeam", "cn_name": "胶缝", "is_defect": true, "in_train_set": true}
  ]
}
```

`name` 必须与模型输出类名及客户「AI模型缺陷标签」一致。`is_defect=false` 为**屏蔽非缺陷**（残带/钻孔/锯齿/标签），默认不启用、不进入对外结果。核心缺陷与屏蔽名单见 `03.类别角色核心缺陷与屏蔽.md`。

## 3. 方案 `GET / PUT / POST /v1/scheme`

查询与配置**同一套字段**。边端建议：打开精度页 `GET`，保存方案时 `PUT`（或 `POST`，二者等价）。**不依赖模型是否已加载。**

查询响应：

```json
{
  "code": 0,
  "scheme_name": "20260605",
  "mm_per_px": 0.03,
  "channels": {
    "ng": true,
    "ng_area": true,
    "label": true,
    "label_area": false,
    "discharge": true,
    "discharge_area": false
  },
  "defects": [
    {
      "name": "GlueSeam",
      "cn_name": "胶缝",
      "enable": true,
      "confidence": 0.30,
      "detect_when_laminating": false,
      "area_mm2": 0,
      "ng": {"height_mm": 0.15, "logic": "or", "length_mm": 5.0},
      "label": {"height_mm": 0.40, "logic": "and", "length_mm": 5.0},
      "discharge": {"height_mm": 0.40, "logic": "and", "length_mm": 5.0}
    }
  ]
}
```

`logic`：`or`（或）/ `and`（与）/ `length_only`（仅长度）。也可写中文 `或` / `与` / `仅长度`。高度、长度均为 0：该通道关闭。

| `channels` | 对应精度页表头 | 说明 |
|:---|:---|:---|
| `ng` / `label` / `discharge` | NG / 贴标 / 排出 | 通道总开关 |
| `ng_area` / `label_area` / `discharge_area` | 各通道旁的「面积」 | 该通道是否套用本行 `area_mm2` |

三类共用该行 `area_mm2`；未勾该通道「面积」、或 `area_mm2<=0`，该通道不按面积过滤。旧字段 `channels.area` 仅写入时兼容，等同未传 `ng_area` 时的 `ng_area`；查询不再返回 `area`。

### 配置 `PUT /v1/scheme`（`POST` 相同）

Body 与 GET 结构相同，可直接回写 GET 全文（`code`/`msg`/`engine` 会被忽略）。

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| `scheme_name` / `mm_per_px` / `channels` / `defects` | 同 GET | 至少一个 | 要改的字段 |
| `persist` | bool | 否 | 是否写盘，默认 `true` |
| `replace` | bool | 否 | `false`（默认）按 `name` **合并**未出现的类保持原值；`true` 时 `defects` 整表替换（必须带 `defects` 数组） |

只改开胶置信度：

```json
{"defects": [{"name": "Tackless", "confidence": 0.50}]}
```

保存成功返回当前完整方案（同 GET），并多 `msg`、`persisted`：

```json
{"code": 0, "msg": "ok", "persisted": true, "scheme_name": "20260605", "defects": []}
```

失败 `msg`：`请求body必须是JSON` / `请求body无有效方案字段` / `replace时必须提供defects数组` / `写入方案文件失败`

配置立即成为后续 `POST /v1/predict` 的默认方案（预测里仍可带 `scheme` 作**单次**覆盖，不写盘）。

## 4. 判定规则（与客户「精度」页一致）

对每个检测框：

1. 类未 `enable` → 丢弃（不出现在 `results`）。
2. `laminating==true` 且该类 `detect_when_laminating==false` → 丢弃。
3. `score < confidence` → 丢弃。
4. `height_mm = min(有效宽,有效高) * mm_per_px`；`length_mm = max(有效宽,有效高) * mm_per_px`。有效宽高取自结果 `obb.width/height`（detect 的轴对齐框已展开为 angle=0 的 OBB）。
5. 通道命中：
   - `or`：高度>H **或** 长度>L
   - `and`：高度>H **且** 长度>L
   - `length_only`：仅长度>L
6. 面积：`area_ok = (area_mm2<=0) 或 (框面积 > area_mm2)`。通道勾了对应「面积」（`ng_area` / `label_area` / `discharge_area`）时，该通道命中 = 尺寸规则 **且** `area_ok`；未勾则只看尺寸规则。
7. 未知类名：仍返回，`cn_name=""`，`ng/need_label/need_discharge` 均为 `false`（不改变 `board_ok`）。

默认方案数值对齐客户方案 `20260605`（见关联截图）；现场以请求下发或服务配置为准。

覆盖示例（对象包一层）：

```json
{
  "cameras": [{"camera": "ch1", "images": ["C:/data/a.bmp"]}],
  "laminating": false,
  "calib": {"mm_per_px": 0.029},
  "scheme": {
    "defects": [
      {"name": "Tackless", "enable": true, "confidence": 0.45, "ng": {"height_mm": 1.0, "logic": "or", "length_mm": 5.0}}
    ]
  }
}
```

未出现在覆盖数组里的类保持服务默认。

## 6. 调用示例

```bash
curl -s http://127.0.0.1:37870/health/ready
curl -s http://127.0.0.1:37870/v1/scheme

curl -s -X PUT http://127.0.0.1:37870/v1/scheme \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{"defects":[{"name":"Tackless","confidence":0.5,"enable":true}]}'

curl -s -X POST http://127.0.0.1:37870/v1/predict \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{"infer_type":"obb","cameras":[{"camera":"ch1","images":["/data/edge/a.bmp"]}]}'

# 上传（跨机/无共享盘）
curl -s -X POST http://127.0.0.1:37870/v1/predict/upload \
  -F 'camera=ch1' -F 'infer_type=obb' -F 'files=@/data/edge/a.bmp'
```

Windows 边端路径接口用绝对路径，例如 `D:\\line\\pic\\xxx.bmp`；JSON 中反斜杠需转义。路径原样使用，服务不做盘符改写。
