# 功能设计

第一版仿昆虫入口，但流水线按封边缺陷裁剪：**单检测模型 + 方案过滤 + 物理判定**，暂不做嵌套分类路由。

```
边端提交 [ {camera, images[]} ]  （路径）
或 multipart files + meta.cameras[].count  （上传）
  → 按相机、按图顺序读盘 / 解码
  → （可选切片）YOLO 检测 + 方案过滤 + NG/贴标/排出
  → [ {camera, defects: [ 图1缺陷[] , 图2缺陷[] ]} ]
```

实现目录：`scanly/defects/predict/`。

| 文件 | 职责 |
|:---|:---|
| `labels.py` | 类别对照常量 |
| `scheme.py` | 方案加载、逻辑归一化、单框判定 |
| `predict_all.py` | `DefectPredictAll`：加载 YOLO、切片检测、NMS、过滤 |
| `api_models.py` | OpenAPI 请求/响应模型，供 `/docs` 展示结构与示例 |
| `serve.py` | FastAPI 路由 + Gradio；路径预测与 multipart 上传；`gr.mount_gradio_app` 挂载 |
| `config/scheme.json` | 默认方案 `20260605` |
| `config/predict.json` | 模型路径、`infer_type`、切片、默认 `mm_per_px`、端口 |
| `client_example.py` | 本机 HTTP 试调（变量入口，不强制 CLI） |
| `predict_dir.py` | 目录批量离线推理：画框图 + Pascal VOC XML |

## 1. 推理

- 模型后端按权重后缀与 ONNX 图结构选择（实现：`predict_all.py`）：
  - `.pt` / `.engine` / **YOLO 导出 `.onnx`**：Ultralytics `YOLO(..., task=detect|obb)`
  - **RT-DETRv2 导出 `.onnx`**（输入含 `images` + `orig_target_sizes`）：`onnxruntime` 会话；仅 `detect`
- `predict.json` 关键字段：
  - `model_path`：检测（detect）权重（`.pt` / YOLO `.onnx` / RT-DETRv2 `.onnx`）
  - `obb_model_path`：OBB 权重（可空；YOLO-OBB `.pt` / YOLO-OBB `.onnx`）
  - `infer_type`：可选，默认 `obb`（也可配 `detect`）——**决定默认走哪条权重**，不是「文件格式」
  - `imgsz`：RT-DETRv2 ONNX 方形边长；`<=0` 时用模型输入静态维或回退 `1024`
  - `class_names`：RT-DETRv2 类别名（按 class id）；缺省 `["defect"]`
  - `_readme`：配置备注（加载时忽略，仅给人看）
- **`infer_type` 配对规则**（易错）：

| 目标 | `infer_type` | 权重字段 | 说明 |
|:---|:---|:---|:---|
| 轴对齐检测 | `detect` | `model_path` | RT-DETRv2 / YOLO-detect |
| 旋转框 | `obb` | `obb_model_path` | 仅 YOLO-OBB；RT-DETR 无 OBB |
| 只配一个路径且要做 OBB | `obb`（默认） | 只写 `model_path`，`obb_model_path` 留空 | 服务把该路径当 OBB 加载 |

  请求对象可带 `infer_type` 覆盖本次任务；未带则用配置默认。对应权重未加载则预测失败。RT-DETRv2 `.onnx` 若被配成 `obb` 且无独立 OBB 权重：自动按 `detect` 加载并打警告，不把该文件当 OBB。
- **路径解析**：相对路径（如 `cam2-0819.pt`）相对 `scanly/defects/predict/models/`；绝对路径原样使用。
- **输出**：每条缺陷均带 `obb`（四点）。detect 将轴对齐框展开为 `angle=0` 的矩形四点；obb 用模型旋转框。`height_mm`/`length_mm`/`area_mm2` 均按 `obb.width/height` 计算。
- `clip_size=0`：整图；`>0` 时按 `overlap_size` 切块，坐标加偏移后按 IoU NMS（OBB 切块融合暂用外接框 IoU）。
- 一次加载，进程内复用；GPU 推理加锁。detect 与 obb 可同时驻留。
- 无权重文件：进程仍可启动；`/v1/labels`、`/v1/scheme` 可用；`/v1/predict` 与 `/health/ready` 报告未就绪。
- **Scope Out**：本版不解密 `.onnx.enc`（仍走 `predict_go`）；不在 Python 服务内加载 RT-DETR `.pth`。

## 2. 方案查询与配置

启动加载 `scheme.json`。`GET /v1/scheme` 返回当前进程方案。`PUT`/`POST /v1/scheme` 按 `name` 合并或整表替换，默认写回同一文件；立即作为后续预测的默认方案。模型未加载时配置接口仍可用。

预测请求带 `scheme.defects[]` 时按 `name` 深合并，**只影响该次推理**、不写盘。Gradio 勾选仅本次内存生效，不走配置接口、不写盘。

判定公式见接口文档第 4 节。`channels.ng/label/discharge` 为通道总开关；`ng_area/label_area/discharge_area` 对应精度页各栏旁的「面积」勾选（三类共用 `defects[].area_mm2`）。某一通道关闭则对应布尔字段恒为 `false`。

## 3. HTTP（须先注册再挂 Gradio）

与昆虫相同：先建独立 `FastAPI`，注册 `/v1/predict` 等，再 `gr.mount_gradio_app`。预测在线程池中执行，主协程不阻塞。

`/v1/predict` 与 `/scanly_predict` 相同：Body 为相机数组或 `{cameras, infer_type, ...}` 对象。`infer_type` 为 `detect` / `obb`。返回 `results[{camera, defects[][]}]`，缺陷含 `location`；obb 另含 `obb.points`。请求/响应用 Pydantic 模型声明。

`/v1/predict/upload`：`multipart/form-data`，字段 `files` + 可选 `meta`（JSON 字符串，含 `cameras[].count`）或简写 `camera`。服务将上传内容写入临时目录，组装与路径接口相同的 `cameras[].images` 后复用 `predict_http`；请求结束后删除临时文件。响应与路径接口相同。Go 服务本迭代可不实现该路径。

错误体：`{"code":500,"msg":"..."}`。

## 4. Gradio

单页：上传图、`infer_type`、`mm_per_px`、覆膜开关、类别启停、运行识别；右侧结果图（obb 画四点多边形）；下方结果表与**本次检出 JSON**；另有一栏方案配置 JSON（`defects[]` 为各类阈值，不是检出列表）。结果图标签使用系统中文字体（Ubuntu 需 `fonts-wqy-microhei` 或 `fonts-noto-cjk`）。

# 数据模型

配置不以数据库存储。`scheme.json` 中每条 `defects[]` 对应接口文档方案字段。预测量纲：像素框整数；mm 保留两位小数。`predict.json` 的 `infer_type` / `obb_model_path` 为进程默认，请求可覆盖类型。

# 约束与边界

- 不做相机 SDK、硬触发、共享内存。多相机按请求中的路分别推理，不做跨相机框融合；`board_ok` 为各图 NG 的 OR。
- 不实现客户 UI 的方案另存/导入文件对话框；边端用 `PUT /v1/scheme` 写入当前方案即可。
- 不在此版做 TensorRT 编译；有 `.engine` 则按 Ultralytics 方式加载。
- 明文 `.onnx` 支持 YOLO 导出与 RT-DETRv2 导出；不解密 `.onnx.enc`（仍走 Go）。
- 未知类名进入 `results` 但不置 NG。
- 屏蔽非缺陷（`ResidualTape`/`Hole`/`Zigzag`/`Label`）`is_defect=false`，默认 `enable=false`，不进入对外结果。
- `Above`/`BandWave` 若当前权重无名，则不会检出，接口与方案仍保留。`Below`/`Shorter`/`BandBroken` 已在训练类别中。
- 切块 NMS 对 OBB 使用外接框 IoU，不实现精确旋转 IoU。

# 关联设计

总架构 InferRequest 的多路路径在本接口以 `cameras[].images` 落地；相机号用边端字符串（不限于 up/mid/down）。

## 5. 目录批量离线（`predict_dir.py`）

复用 `DefectPredictAll` + `predict.json` / `scheme.json`，不启 HTTP。

| `__main__` 变量 | 含义 |
|:---|:---|
| `INPUT_DIR` | 源图目录（扁平，递归可选） |
| `OUTPUT_DIR` | 输出根目录 |
| `LIMIT` | `>0` 时只处理前 N 张（试跑） |
| `COPY_IMAGES` | 是否把原图写入 `JPEGImages/`（硬链优先，失败则复制） |
| `SAVE_VIS` | 是否写 `vis/` 画框图 |
| `SAVE_VOC` | 是否写 `Annotations/*.xml` |

输出布局：

```
OUTPUT_DIR/
  JPEGImages/           # COPY_IMAGES=True
  Annotations/*.xml     # Pascal VOC；无框也写空 object 列表
  vis/*                 # draw_results 画框（含类名/分数）
  predefined_classes.txt
  summary.json          # 张数、检出框数、耗时
```

XML 的 `object/name` 用推理英文类名（如 `defect`）；框取外接矩形（`location` / `obb` 外接）。跳过 macOS `._*` 与非图像后缀。不启服务、不写方案落盘。
