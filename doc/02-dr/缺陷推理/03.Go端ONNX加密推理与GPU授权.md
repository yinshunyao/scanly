# 功能设计

实现目录：`scanly/defects/predict_go/`。产线 HTTP 与 Python 版同一套路径与 JSON 字段；**不挂 Gradio**。默认端口 **37871**，避免与 Python `37870` 冲突。

```
启动
  → 读 license.json，Ed25519 验签
  → 读本机 NVIDIA GPU（uuid/name/serial），与 License 列表做三项全匹配
  → 通过后用 License 内 AES 密钥内存解密 .onnx.enc
  → ONNX Runtime 建会话（不写明文权重文件）
  → 提供 /v1/predict 等接口
```

## 1. License

Python：`predict_go/tools/gen_license.py`（`__main__` 变量入口）。

License JSON：

| 字段 | 说明 |
|:---|:---|
| `version` | `2` |
| `issued_at` / `expires_at` | RFC3339；`expires_at` 空表示不过期 |
| `customer` / `model_id` / `note` | 备注 |
| `gpus` | 至少 1 条。每条含 `uuid`、`name`、`serial`，均不可空 |
| `aes_key_b64` | 对应模型 AES-256 密钥 |
| `signature_b64` | Ed25519，对去掉 signature 后的 canonical JSON（`sort_keys`、紧凑分隔符）签名 |

厂商私钥 PEM 仅签发机保存。Go 用 `go:embed` 公钥验签；换密钥须重新编译服务。

本机 GPU：`nvidia-smi --query-gpu=uuid,name,serial --format=csv,noheader`。规范化：三项去首尾空白；`uuid` 不区分大小写，`name`/`serial` 去空白后精确比较。列表中 **任一** 条与本机某一 GPU **三项全部一致** 才通过；只对上 UUID 或只对上型号都不通过。

校验失败不得解密。`GET /health/ready` 在 License 或模型未就绪时 HTTP 503。`GET /v1/license` 返回是否有效、本机与授权 GPU 的 uuid/name/serial（不回传密钥）。

## 2. 推理

- 加载：`github.com/yalue/onnxruntime_go`，从内存字节建会话。
- 预处理：letterbox 到 `imgsz`、RGB、`/255`、NCHW；pad 值 114（中间结果 float32）。
- **精度**：建会话时读取 ONNX 输入/输出 `DataType`。`float` → 现有 `Tensor[float32]`；`float16` → `NewCustomDataTensor`（IEEE float16 字节）喂入，输出再转回 float32 后解码。兼容 `convert_2_onnx.py` 的 FP32 / FP16 密文；meta 的 `precision` 仅作标识。
- OBB 原始输出 `(1, 4+nc+1, N)`：`cx,cy,w,h,cls...,angle`（弧度）。detect 无 angle。
- 后处理：置信度过滤、按类 AABB-NMS、`xywhr→四点`，坐标从 letterbox 还原。切块融合与 Python 相同（外接框 IoU）。
- 判定：移植 `scheme.py`（启停 / 覆膜 / 置信度 / NG·贴标·排出 / 面积通道）。
- 默认方案文件可指向 `defects/predict/config/scheme.json`，避免两套阈值。

`predict.json`（相对 `predict_go/` 根）：密文路径、meta、License、`ort_lib_path`、`device`、切片与 `conf`/`iou`，以及 TensorRT 相关字段。

| `device` | 含义 |
|:---|:---|
| `cpu` | CPU EP |
| `cuda` / `gpu` | CUDA EP（现网默认） |
| `tensorrt` / `trt` / `trt_fp16` | TensorRT EP（默认 FP16）+ CUDA 作算子回退 |

| 字段 | 默认 | 说明 |
|:---|:---|:---|
| `trt_fp16_enable` | `true`（仅 `tensorrt` 时生效） | 对应 ORT `trt_fp16_enable` |
| `trt_engine_cache_path` | `models/trt_cache` | 引擎缓存目录；首次建引擎较慢，后续复用 |

`device=tensorrt` 时：若 ORT 无 TensorRT EP，或会话实际首位 provider 不是 TensorRT，**直接失败**（不静默当已 TRT 加速）。CUDA 仍挂在 provider 列表中，仅用于 TRT 未覆盖的算子分区。

半精度：TensorRT 线用 **FP32 ONNX + `trt_fp16_enable=true`**（由 EP 在建引擎时做 FP16）。**不要**把 Ultralytics `half` 导出的 FP16 ONNX 再叠一层 TRT FP16（V100 / TRT 8.6 上 OBB 解码易 NaN）。FP16 密文继续给 `device=cuda` 使用。解码须跳过 NaN/Inf 框，避免 `round` 转整数崩溃。

默认 ORT 目录（`ort_lib_path` 为空时按 OS 自动选择）：

| 平台 | 目录 | 默认库名 |
|:---|:---|:---|
| Linux / macOS | `third_party/onnxruntime/` | `libonnxruntime.so` / `.dylib` |
| Windows | `third_party_win/onnxruntime/` | `onnxruntime.dll` |

仍可用 `ort_lib_path` 覆盖为任意路径。

Go 依赖 `github.com/yalue/onnxruntime_go` 与现场 ORT **动态库必须配对**。仓库发布 **两个二进制**（`tools/build_dual.sh`）：

| 产物 | 绑定 | 现场 ORT |
|:---|:---|:---|
| `scanly-defects-go` | v1.26（API 24） | ≥1.24 |
| `scanly-defects-go-ort118` | v1.11.0（API 18） | **1.18.1** |

细节见 `scanly/doc/99-ops/run_go.md` §2.1。

## 3. HTTP

与 `01.HTTP接口文档.md` 相同：`/health/ready`、`/v1/predict`、`/scanly_predict`、`/v1/labels`、`GET|PUT|POST /v1/scheme`。新增：

- `GET /v1/license`：授权状态
- `GET /`：服务说明 JSON（不是 Gradio）

`engine` 为 `scanly-defects-go-v1`。业务错误仍 HTTP 200 + `code=500`。License / GPU 失败 `msg`：`许可证无效` / `许可证已过期` / `未检测到NVIDIA GPU` / `本机GPU信息与授权不一致` / `模型解密失败`。

# 约束与边界

- 不在 Go 内加载 `.pt`，不内嵌 Python。
- 不把私钥、`.key.json`、明文 ONNX 打进现场包。
- CUDA / TensorRT 通过 ONNX Runtime EP；配置要求 GPU/TRT 时失败不得静默当已加速成功。
- 开发机无 NVIDIA 时 License 不能通过；不要在生产配置里提供 GPU 覆盖开关。
- TensorRT 引擎缓存可写盘（非模型明文）；勿把缓存当权重交付物。

## 5. Python 冒烟（非产线）

`predict_go/server_onnx.py`：共用 `config/predict.json`、License、`.onnx.enc`；用 **pip `onnxruntime-gpu`** 建会话（不加载 `third_party` C 库）。用于隔离「GPU/cuDNN 是否可用」。默认监听 **37872**。产线仍以 Go + 下载的 ORT 包为准。按 session 输入 dtype 自动喂 `float32` / `float16`，与 Go 一样兼容两种精度密文。

性能对比：`scanly/defects/test/test_onnx_infer_perf.py` 复用 `server_onnx` 的解密与 `OnnxEngine`，对配置的 FP32/FP16 模型同图计时（warmup + N 次），打印 mean/p50/p95 与相对加速比；`DEVICE` 支持 `cuda` / `tensorrt`（可配 `TRT_ENGINE_CACHE_PATH`）。

V100 + 现网 CUDA12/cuDNN9 上 ORT≥1.20 易 CUDNN_FE 失败时：按 `scanly/doc/99-ops/run_go_cuda11.md` 并排 **CUDA 11.8 + cuDNN 8 + ORT 1.18.1**，启动前 `source predict_go/env_cuda11.sh`。`device=tensorrt` 还须现场 ORT/Python 包带 TensorRT EP 且系统已装匹配的 TensorRT。
