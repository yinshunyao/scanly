# 功能设计

## 入口与配置

实现目录：`scanly/train/`。`train.py` 为检测训练入口，`test.py` 为检测测试集验证入口，`train_obb.py` 为 OBB 训练入口。训练入口先调用 `train_detect_cfg/prepare_dataset.py` 再 Ultralytics 训练。

**配置落点（解耦，见 `07.数据配置与训练配置解耦.md`）**：公共数据在 `train_detect_cfg/data_cfg.json`；YOLO 超参在 `train_detect_yolo/train_config.json`；OBB 在 `train_detect_obb/train_config.json`。入口 `__main__` 只指定 `CONFIG_PATH`。

| 配置项（JSON 键） | 含义 |
|:---|:---|
| `source_data_root` | 原始 YOLO 数据集根；`voc_xml_path` 非空时不使用 |
| `voc_xml_path` | 扁平 VOC 根。非空则作为准备源，写出到独立 `output_dir` |
| `train_classes` | 要引入训练的英文类名，顺序即 class id（从 0） |
| `output_dir` | 转换后的 YOLO 根兼训练权重输出根（公共 `data_cfg`；入口可覆盖）；检测与 OBB 宜分目录 |
| `label_format` | `prepare_dataset` 参数：`detect` 或 `obb`（由入口脚本固定传入） |
| `voc_split.val_ratio` / `test_ratio` / `seed` | 按子目录分层划分；`test_ratio>0` 才写出 test |
| `keep_empty_labels` | 过滤后无框是否保留为空标签负样本 |
| `prepare_only` / `skip_prepare` | 只准备 / 跳过准备 |
| `single_cls` | 检测入口：全部框视为一类；默认 `false`。OBB 不暴露 |
| `model_path` / `train.imgsz` / `epochs` / `batch` | 训练超参（入口 JSON） |
| `SPLIT` | 仅 `test.py` 变量：默认 `test` |

## 原始目录发现

路径 `P` 先判定为 Label Studio YOLO 导出包，当同时存在 `images/`、`labels/`、`classes.txt`。

1. `P` 自身是导出包 → 单源。
2. 否则扫描 `P` 的子目录，收集全部导出包并合并。
3. 若未发现 YOLO 包，再判定扁平 VOC：存在 `JPEGImages/`（或 `images`/`Images`）与 `Annotations/`（或 `annotations`）。`P` 自身是 VOC → 单源；否则扫描子目录收集 VOC 根（进入某 VOC 后不再向下搜）。
4. 两种布局都没有 → 报错。

YOLO 与 VOC 源目录禁止与 `OUTPUT_DIR` 相同，以免准备阶段写入 `images/`、`labels/`、`data.yaml` 污染源标注。

`cam123-0820` 走第 2 条，当前子目录包括：`BandBroken`、`Below`、`Bumps`、`ClampGlue`、`GlueGap`、`GlueResidue`、`GlueSeam`、`Hole`、`Label`、`Longer`、`Longer2`、`ResidualTape`、`Scrape`、`Scratch&Rrsidual_tape`、`Shorter`、`Tackless`、`Zigzag`。各子目录 `classes.txt` 长度不同，必须按类名对齐。

默认 `TRAIN_CLASSES` 在 `train.py` 中按「缺陷 / 非缺陷」分组列出，共 18 类。不纳入 `Above`（推理方案关闭，且合并集中框数极少）。`BandBroken2` 无独立子目录，框在 `BandBroken` / `Below` 等包内，仍按类名训练。

`TRAIN_CLASSES` 含核心缺陷与屏蔽非缺陷。屏蔽类（`ResidualTape` / `Hole` / `Zigzag` / `Label`）训练保留，推理默认丢弃；名单与框数见 `03.类别角色核心缺陷与屏蔽.md`。顺序即 class id，与「空列表=全部类别（含 Above，共 19 类）」不同；重新 `prepare` 后才会改 `data.yaml`。

VOC 源（如 `cam2-0911-1024`）类别以 `predefined_classes.txt` 为准；无该文件则按 XML `object/name` 首次出现顺序收集。`TRAIN_CLASSES` 仍按名称过滤；`bndbox` 像素框用 XML `size`（缺失则读图像）归一化为 `cx cy w h`。OBB 入口可将轴对齐框展开为四顶点。不解析 VOC 多边形。

## 类别过滤与 id 重映射

每个子目录独立读取 `classes.txt`（行号 = 该目录 class id，行内容 = 英文名）。标签行先还原为类名，再查 `TRAIN_CLASSES`：

- 在列表中 → 写成新 id（列表下标）。
- 不在列表中 → 丢弃该框。
- `TRAIN_CLASSES` 含原始数据中不存在的名字 → 启动失败，列出可用类名。

禁止跨子目录直接复用数字 id（`Shorter` 在不同目录 id 不同）。VOC 源无数字 id：直接用 XML `object/name` 对齐 `TRAIN_CLASSES`。

## 标签格式转换

按空格拆分标签行；`label_format` 决定写出形态。

### `detect`（`train.py`）

| 形态 | 处理 |
|:---|:---|
| `id cx cy w h`（恰好 4 个数） | 只改 class id，坐标裁剪到 `[0,1]` |
| `id x1 y1 ...`（偶数个坐标且 ≥ 6） | 取 min/max 外接框再转 `cx cy w h` |
| 其它 / 退化 | 跳过并计数 |

### `obb`（`train_obb.py`）

| 形态 | 处理 |
|:---|:---|
| `id x1 y1 x2 y2 x3 y3 x4 y4`（恰好 8 个数） | 只改 class id，坐标裁剪到 `[0,1]`，保留四点 |
| 多于 4 点的多边形 | 取外接轴对齐框再展开为矩形四顶点 |
| `id cx cy w h` | 展开为矩形四顶点 |
| 面积过小 / 非法 | 跳过并计数 |

`cam123-0820` 当前为四顶点（8 坐标）：检测入口走外接框，OBB 入口直接保留四点。

## 输出布局

```
OUTPUT_DIR/
├── classes.txt
├── data.yaml
├── stats.json
├── images/train/
├── images/val/
├── images/test/      # TEST_RATIO>0 时写出
├── labels/train/
├── labels/val/
└── labels/test/
```

多子目录合并时图像 stem 加 `{子目录名}__` 前缀，避免重名。`data.yaml` 的 `names` 与 `TRAIN_CLASSES` 一致。`val` 为空时回退 `val: images/train`。`TEST_RATIO>0` 时写出 `test: images/test`。

样本过少（某子目录 ≥2 张且 `VAL_RATIO>0`）时至少留 1 张 val；仅 1 张则全部进 train。

## 训练

| 入口 | 任务 | 默认权重 | 默认上限 / 早停 |
|:---|:---|:---|:---|
| `train.py` | `detect` | `yolo11s.pt` | `EPOCHS=200`，`PATIENCE=25` |
| `train_obb.py` | `obb` | `yolo11s-obb.pt` | `EPOCHS=200`，`PATIENCE=30`（本版不改） |

`patience` 原样传给 Ultralytics：监控 val fitness（以 mAP50-95 为主），连续该 epoch 数不刷新 `best.pt` 则停；`epochs` 只是上限。检测默认 25 与 insect `train_ba` 同量级，避免 `150/50` 时最佳轮次偏后却跑满上限。

设备：Linux 优先 `cuda:0`，macOS 优先 `mps`，否则 `cpu`；`mps` 关闭 AMP。权重写到配置的 `TRAIN_PROJECT`（默认 `scanly/train/runs/`）。检测入口不传 `name`、`exist_ok` 保持默认 `False`，Ultralytics 自动使用 `train`、`train2`、`train3`…，不覆盖已有目录。`test.py` 仍可指定 `RUN_NAME`（默认带 `-test` 后缀），以免写入训练 run。OBB 本版不改推理 `scheme.json` / `labels.py`；检测权重仍可配进 `predict.json`。

`SINGLE_CLS=True` 时：`TRAIN_CLASSES` 仍决定纳入哪些框（准备阶段过滤）；训练阶段 Ultralytics 将各类 id 视为 0，产出 `nc=1` 的检测权重。默认 `False`，与多类 `data.yaml` 行为一致。单分类权重与现有按类名屏蔽的推理方案不兼容，需单独部署。

## 测试集验证

入口：`scanly/train/test.py`。复用 `train.py` 的 `resolve_device` / `sync_data_yaml_path`，不对原始数据再 prepare。

1. 同步 `OUTPUT_DIR/data.yaml` 的 `path`。
2. 确认 `SPLIT`（默认 `test`）在 yaml 中有对应字段，且 `images/{split}` 非空；否则报错，提示 `TEST_RATIO>0` 后重新准备。
3. 解析 `MODEL_PATH`（相对路径相对 `scanly/train/`），文件不存在则报错。
4. 调用 `YOLO.val(data=..., split=SPLIT, imgsz, batch, device, workers, single_cls, project, name)`。
5. 日志打印 mAP50 / mAP50-95；将 `results_dict` 与每类 mAP 写入 `{TRAIN_PROJECT}/{RUN_NAME}/test_metrics.json`。默认 `RUN_NAME` 带 `-test` 后缀，避免覆盖训练 run。

# 约束与边界

- 不写回、不删除原始 `样本数据/` 与 VOC 源目录。
- 不在此版做分割训练（YOLO-seg）、不自动从 Label Studio 拉图。
- 不把 `insect/train` 整套合并管线搬入；本目录适配封边 YOLO 导出包与扁平 VOC。
- 配置类别在数据中样本为 0 时仍保留该类名并告警，不静默删 id。
- OBB 训练产出不要求本版推理服务可加载。
- OBB 本版不提供独立测试集验证入口（`test.py` 仅检测）。
