# 功能设计

入口：`scanly/train/convert_2_onnx.py`。参数在 `__main__` 变量区，风格与 `train.py` / `train_obb.py` 一致。

```
.pt（Ultralytics YOLO11 detect 或 obb）
  → export ONNX（固定 imgsz，不内嵌 NMS；可选 half=FP16）
  → 写出 meta.json（task / imgsz / names / precision）
  → AES-256-GCM 加密 → .onnx.enc
  → 写出 .key.json（仅厂商侧，含 aes_key_b64）
```

| 变量 | 含义 |
|:---|:---|
| `MODEL_PATH` | 训练产出 `best.pt` 或其它 `.pt`；相对路径相对 `scanly/train/` |
| `TASK` | `detect` 或 `obb` |
| `IMGSZ` / `OPSET` | 导出尺寸与 opset，默认 640 / 17 |
| `NMS` | 默认 `False`，后处理在 Go 侧 |
| `HALF` | 默认 `True`：Ultralytics `half=True` 导出 FP16 ONNX；`False` 为 FP32 |
| `DEVICE` | 导出设备。`HALF=True` 时**必须**为 GPU（如 `0` / `cuda`）；`cpu` 会直接失败 |
| `SANITIZE_LD_LIBRARY_PATH` | 默认 `True`：GPU/FP16 导出前清空**本进程** `LD_LIBRARY_PATH`，避免系统 CUDA11/cuDNN（常为 Go ORT 配置）覆盖 PyTorch wheel 自带库 |
| `KEEP_PLAIN_ONNX` | 是否保留明文 `.onnx`，**默认是**（人工删除后再打现场包）；`False` 时脚本自动删明文。**原始 `.pt` 始终保留，本脚本从不删除** |
| `OUTPUT_DIR` | 默认 `scanly/train/output/onnx/` |
| `MODEL_ID` | 写入 meta / key，供 License 对应 |
| `AES_KEY_PATH` | 已有密钥则复用，否则新生成 32 字节 |

加密格式：魔数 `SLYENC01`（8 字节）+ 12 字节 nonce + AES-GCM 密文（含 tag）。AAD 固定 `scanly-defects-onnx-v1`。实现：`scanly/train/model_crypto.py`。

`meta.json` 不含权重，可随密文一起交给 Go（`names` 供类名映射）。另写：

| 字段 | 说明 |
|:---|:---|
| `precision` | `fp16`（`HALF=True`）或 `fp32` |
| `half` | 与 `HALF` 一致的布尔值（便于脚本读取） |

`.key.json` 只用于 Python 签发 License，禁止放入现场包。

推理侧（Go / `server_onnx.py`）以 **ONNX 实际输入/输出 dtype** 为准喂数与解码（优先于 meta）；meta 的 `precision` 仅作交付标识。FP16 图的输入输出一般为 float16，预处理仍在 float32 完成后再转换。

# 约束与边界

- 不在此脚本训练；输入必须是已有 `.pt`。
- **不删除**输入的原始 YOLO `.pt`（`MODEL_PATH`），仅可能按开关删除明文 `.onnx`。
- 不在此签发 License（见 `predict_go/tools/gen_license.py`）。
- 导出依赖 Ultralytics；加密依赖 `cryptography`。
- 本脚本不做 INT8 / TensorRT；半精度仅 Ultralytics ONNX `half`。
- 同一机若为 Go ORT 设置了 `LD_LIBRARY_PATH`（如 `cuda-11.8`），与 `torch+cu12x` 冲突时可能出现 `GET was unable to find an engine`；默认 `SANITIZE_LD_LIBRARY_PATH=True` 规避；仍失败可 `HALF=False` 或手工 `LD_LIBRARY_PATH= python3 convert_2_onnx.py`。
