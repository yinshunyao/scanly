# 功能设计

## 目录与入口

| 路径 | 职责 |
|:---|:---|
| `scanly/train/train_rtdetrv2.py` | 封边 RT-DETRv2 训练入口：准备数据 → YOLO 转 COCO → 训练 → 训练后 val/test 评估 |
| `scanly/train/test_rtdetrv2.py` | 对训练产出 `.pth` / `.onnx` 做指定划分（默认 test）COCO 评估 |
| `scanly/train/prepare_dataset.py` | 与 `train.py` 共用，写出 YOLO 检测目录 |
| `scanly/train/rtdetrv2_pytorch/` | 自包含 RT-DETRv2 PyTorch 实现（模型、solver、YAML） |

入口参数在 `__main__`：默认 `CONFIG_PATH` 指向 `train_detect_core/train_config.json`；另可设 `TEST_ONLY` / `RESUME`。数据项与 YOLO 共用 `train_detect_cfg/data_cfg.json`（含 `voc_xml_path`、`train_classes`、划分）；训练项（yaml、预训练、超参、`output_dir`）在 `train_detect_core/train_config.json`。调用 `prepare_dataset` 时按函数签名过滤未知关键字（现场旧副本可能无 `test_ratio`）；忽略后只划分 train/val，仍可训练。

## 数据流

```
VOC / Label Studio YOLO
        │  prepare_dataset(label_format=detect)
        ▼
OUTPUT_DIR（YOLO：images/{train,val,test} + labels + data.yaml）
        │  转 COCO json（图片仍用 YOLO images 目录，可软链）
        ▼
OUTPUT_DIR/coco/annotations/instances_{train,val,test}.json
        │  YAMLConfig + DetSolver
        ▼
TRAIN_PROJECT/rtdetrv2[_N]/best.pth、last.pth
        │  fit 结束后加载 best.pth（无则 last.pth）
        ├─ val → run 目录 val_metrics.json
        └─ TEST_RATIO>0 且 images/test 有图 → test_metrics.json
        │  再按开关导出同目录 ONNX
```

`SKIP_PREPARE=True` 时要求 `OUTPUT_DIR/data.yaml` 已存在，并同步 `path` 为当前机器路径（复用 `train.py` 的 `sync_data_yaml_path`）。

类别名优先读 `OUTPUT_DIR/classes.txt`，与 `data.yaml` 的 `names` 一致。`SINGLE_CLS=True` 时 COCO `categories` 仅一类、全部框 `category_id=0`，不改写 YOLO txt。

COCO `category_id` 与 YOLO class id 同为从 0 计；`remap_mscoco_category=False`。`num_classes` 为训练类数（单类为 1）。空标签图仍写入 images（负样本），该图无 annotation 条目。

val 无图时 COCO val 复用 train json 与 train 图片目录。train 无图则失败。

## 模型与超参

默认 yaml：`rtdetrv2_pytorch/configs/rtdetrv2/rtdetrv2_r50vd_scanly.yml`（ResNet-50 / RT-DETRv2-L）。同目录提供 R18、R34 yaml，改入口 `MODEL_YML` 与对应 `TUNING` 即可。微调时 `PResNet.pretrained=False`，从 `TUNING` 的 COCO 检测权重加载；文件不存在则按 `TUNING_URL` 下载到该路径。

入口把 `imgsz`、`epochs`、`batch`、`workers`、`device`、数据路径写入 YAMLConfig 覆盖项。训练增强与官方 dataloader 一致（光度扰动、RandomIoUCrop 等），最后 `close_mosaic` 个 epoch 关闭 crop/zoom 类增强。`mps` / `cpu` 关闭 AMP。

| 项 | 默认 | 说明 |
|:---|:---|:---|
| `IMGSZ` | 1024 | 与当前检测 `train.py` 对齐 |
| `EPOCHS` | 200 | 上限 |
| `PATIENCE` | 25 | val fitness 连续不升高则停；0 关闭 |
| `BATCH` | 2 | R50@1024 显存保守值 |
| `VAL_FITNESS_METRIC` | `ap50` | 选 `best.pth` 的指标 |
| `TRAIN_PROJECT` | `scanly/train/runs` | 已存在则 `rtdetrv2_2`、`rtdetrv2_3`… |

`RESUME` 非空时写入该 checkpoint 所在目录，不新开编号。`TEST_ONLY=True` 只对 **val** 评估，不跑训练后 val/test、不导出 ONNX。测试集事后补评见 `06.RT-DETRv2测试集验证.md`。

`fit` 正常结束后：释放训练 runtime 与分布式上下文，加载 `best.pth`（无则 `last.pth`），调用 `test_rtdetrv2.run_val`（延迟 import，避免与训练入口循环依赖）。顺序固定为先 val、再 test。val 划分与训练时相同（`images/val` 无图则用 train）。`TEST_RATIO<=0` 或 test 无图则跳过 test 并打日志，训练本身不失败。指标写在该次 run 目录：`val_metrics.json`、`test_metrics.json`。评估完成后再按开关导出 ONNX。无 checkpoint 时跳过评估与 ONNX。

设备：沿用 `train.py` 的 `resolve_device`；传入 solver 时 `cuda:*` 规范为 `cuda`。

## 约束与边界

- 不引用 scanly 以外工程目录的训练模块。
- 不写回 `样本数据/` 与 VOC 源。
- 本版不改推理服务、不走 `convert_2_onnx.py` 加密链路。
- 不在此入口做 OBB / 分割训练。
