# 功能设计

## 入口

`scanly/train/test_core.py`。配置在 `__main__` 变量区。不对原始数据 prepare。

| 配置项 | 含义 |
|:---|:---|
| `OUTPUT_DIR` | 已预处理 YOLO 检测目录（与训练入口同一套 staging） |
| `MODEL_PATH` | `best.pth` / `last.pth` 或训练导出的 `best.onnx` |
| `MODEL_YML` | 与训练一致的 yaml（`.pth` 必填；`.onnx` 用于搭相同 val 预处理与 COCO evaluator） |
| `IMGSZ` / `BATCH` / `WORKERS` / `DEVICE` / `SINGLE_CLS` | imgsz/单类等须与训练一致；`.onnx` 时 `BATCH` 会被强制为 1 |
| `SPLIT` | 默认 `test`，可改为 `val` |
| `TRAIN_PROJECT` / `RUN_NAME` | 指标输出目录；默认 `RUN_NAME` 带 `-test` |
| `SAVE_VIS` | 是否在评估时画框图并记录预测置信度；默认 `True` |
| `VIS_CONF` | 仅用于画图/记录的分数下限（默认 `0.25`）；**不影响** COCO mAP |
| `VIS_IOU` | TP 判定 IoU 阈值（默认 `0.5`）；同类且 IoU≥阈值为 TP |

`map50` / `per_class_*` 仍是全体类别。公共 `val_classes` 非空时，指标文件另写 `val_select`：只含这些类的不加权 AP / AP50 / fitness。`test_core.py` 入口从 `data_cfg.json` 读取该列表。

相对 `MODEL_PATH` 相对 `scanly/train/`。复用 `test.py` 的 `resolve_model_path`、`assert_split_ready`。COCO 写出与评估用 YAML 覆盖项在 `test_core.py` 内实现，只引用训练入口已有符号（`DETECT_CORE_ROOT`、`read_class_names`、`solver_device`、`yolo_split_to_coco`）。可视化辅助在 `scanly/train/test_core_vis.py`，仅被 `test_core.py` 使用。

## 流程

```
OUTPUT_DIR（images/{split} + labels + data.yaml）
        │  同步 data.yaml path；检查 split 非空
        │  YOLO staging → coco/annotations/instances_{split}.json
        ▼
MODEL_PATH 后缀
        ├─ .pth  → YAMLConfig + 评估循环（model/ema + postprocessor）
        └─ .onnx → 同一 val dataloader 预处理，ONNX Runtime 推理，CocoEvaluator 汇总
        │  （可选 SAVE_VIS）按图匹配 GT、画框、写预测记录
        ▼
TRAIN_PROJECT/RUN_NAME/test_metrics.json
        +（SAVE_VIS）vis/*.jpg、predictions.jsonl、vis_summary.json
```

`.pth` 通过 `resume` 加载完整 solver state（含 ema，若 checkpoint 中有）；评估循环与 `DetSolver.val` 等价（更新 CocoEvaluator），便于同趟收集预测做可视化。`.onnx` 输入为 `images` + `orig_target_sizes`，输出 `labels` / `boxes` / `scores`。`orig_target_sizes` 为原图宽高，框坐标与 COCO GT 同为原图像素。`.onnx` **强制 dataloader batch=1**。单独重导用 `export_core.py`。

不按分数阈值过滤 query（评估路径），与训练 val 的 top-300 后处理对齐。`VIS_CONF` 只过滤画图与 `predictions.jsonl` 条目。

YOLO `.pt`：直接失败并提示使用 `scanly/train/test.py`。

## 指标

从 COCO bbox `stats` 取 AP（mAP50-95）、AP50、AP75、AR100；从 `eval['precision']` 按类汇总 AP50 与 AP50-95；从 `eval['recall']` 取每类 IoU=0.5、area=all、maxDets=100 的召回。无该类真值时召回写 `null`。`test_metrics.json` 字段：

- `backend`：`pth` 或 `onnx`
- `split`、`model`、`map50`、`map50_95`、`map75`、`ar100`
- `results`：COCO 12 项 stats
- `per_class_map50` / `per_class_map50_95` / `per_class_recall50`
- `save_dir`

日志在总体 mAP 之后按类各打一行：`类名 AP50 AP R50`。`single_cls=true` 时类名只有 `defect`。这里的召回是「IoU≥0.5 时最多能找回多少真值框」，不是固定置信度下的精确率。
- （`SAVE_VIS` 时）`vis_dir`、`predictions_path`、`vis_summary_path`

独立入口默认 `test_metrics.json`。训练 `fit` 后自动评估写 `val_metrics.json` / `test_metrics.json`。训练入口的 val 不画图；test 评估默认画图，写到该次 core run 目录的 `vis/`，入口 `save_vis` 可关。独立 `test_core.py` 仍由 `SAVE_VIS` 控制，默认打开。

## 推理时延

`run_val(..., record_latency=True)` 时，按批把推理毫秒摊到每张图。`.pth` 计 forward + 后处理，CUDA 上计时前后 `synchronize`。`.onnx` 只计 `session.run`。不含读图、画框和 `CocoEvaluator`。调用多于一次时丢掉第一次。结果写入指标文件的 `latency`（`unit`、`images`、`warmup_excluded`、`mean_ms`、`p50_ms`、`p95_ms`、`min_ms`、`max_ms`、`batch`、`scope`），并打一行日志。默认 `record_latency=False`。训练入口只对 test 打开；独立入口不打开。

## 可视化

- 原图从 `img_folder` + COCO `file_name` 读取；GT 从 COCO ann（原图像素 xyxy），预测用后处理输出。
- 匹配：预测按分数降序贪心，同类且 IoU≥`VIS_IOU` → TP（绿）；其余预测 → FP（红）；未匹配 GT → FN（橙）。
- 预测框旁标注 `类名 score`；FN 的 GT 标注类名。先画框再写字。标签矩形相交时，后一条先下移，下方放不下再右移。
- `predictions.jsonl`：每行一图，含 `file_name`、`predictions[{label,score,box,match}]`、`ground_truth[{label,box,match}]`。
- `vis_summary.json`：TP/FP/FN 计数与 `vis_conf` / `vis_iou`。
- 实现禁止 import `scanly/defects` 或其它 train 外业务目录。

## 约束与边界

- 不写回 `样本数据/` 与 VOC 源。
- 不评估加密 `.onnx.enc`、不接入 Go 推理。
- 不评估 YOLO 风格权重；检测 core ONNX 与 `tools/convert_2_onnx.py` 产物不是同一条链路。
- `TEST_ONLY` 仍只做训练 run 的 val。本入口负责事后补评（或显式 `SPLIT=val`）。
- 不画 PR 曲线图。
