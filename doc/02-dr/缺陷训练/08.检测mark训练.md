# 功能设计

## 目录与入口

| 路径 | 职责 |
|:---|:---|
| `scanly/train/train_mark.py` | 检测 mark 训练入口：按公共配置准备 YOLO 目录，再训练；训练后对 test 画框 |
| `scanly/train/test_mark.py` | 只做 test 画框，不训练 |
| `scanly/train/train_detect_mark/train_config.json` | 规格、续训、准备开关与超参 |
| `scanly/train/train_detect_cfg/` | 公共数据，本入口不复制源路径与类别 |

`__main__` 只设 `CONFIG_PATH`，默认指向 `train_detect_mark/train_config.json`。合并规则与 `07.数据配置与训练配置解耦.md` 相同。

## 数据流

```
VOC / Label Studio YOLO
        │  prepare_dataset(label_format=detect)
        ▼
output_dir（data.yaml + images/{train,val,test} + labels）
        │  同步 data.yaml 的 path 为当前机器绝对路径
        ▼
output_dir/<run_prefix>[_N]/  检查点与训练日志
```

`skip_prepare=true` 时要求 `output_dir/data.yaml` 已存在，并同步 `path`。`prepare_only=true` 时写出数据后返回，不加载运行库。`skip_prepare=true` 且 `prepare_only=true` 视为配置错误。

类别以准备结果里的 `data.yaml` `names` 为准，与公共 `train_classes` 顺序一致。本入口不改写标签文件，因此 `single_cls=true` 在真正训练前失败。

val 为空时，现有准备逻辑已把 `data.yaml` 的 `val` 指回 `images/train`，本入口不再特殊处理。

## 规格与超参

| `size` | 默认边长 | 边长须整除 |
|:---|---:|---:|
| `n` | 384 | 32 |
| `s` | 512 | 32 |
| `m` | 576 | 32 |
| `l` | 704 | 32 |
| `b` | 560 | 56 |

上表是各档预训练权重的出厂边长。本入口默认 `size=s`、`imgsz=1024`，与检测 core / YOLO 对齐：胶缝在 512 上会缩到约半个分块，框更贴不住。`s` 的 1024 能被 32 整除，训练时按边长重算位置编码。显存不够把 `batch` 降到 2，并把 `grad_accum_steps` 提到 2。`b` 不能用 1024。入口在调用训练前按上表的整除约束校验，不通过则不开始训练。已有 512 的检查点不要 `resume` 到 1024。

| 项 | 默认 | 说明 |
|:---|:---|:---|
| `epochs` | 80 | 上限 |
| `batch` | 4 | 整数；显存不够再配合 `grad_accum_steps` |
| `grad_accum_steps` | 1 | 须 ≥ 1 |
| `patience` | 25 | 大于 0 则早停；0 表示跑满 `epochs` |
| `workers` | 4 | 传给数据加载 |
| `lr` | 0.0001 | 微调学习率 |
| `weight_decay` | 0.0001 | |
| `checkpoint_interval` | 10 | 每隔该 epoch 数存一次完整检查点 |
| `run_prefix` | `mark_s` | 换 `size` 时建议一起改 |
| `device` | 空 | 空则与 `train.py` 相同自动选择；`cuda:*` 规范为 `cuda` |

运行库按 `size` 在进程内选择对应类。类名与模块名在运行时拼接，配置和日志只出现 `n` / `s` / `m` / `l` / `b`。

## 输出文件

一次 run 目录里常见：

| 文件 | 含义 |
|:---|:---|
| `last.ckpt` | 最近一次完整检查点，用于 `resume` |
| `checkpoint_best_ema.pth` | 验证指标最好的平滑权重 |
| `checkpoint_best_total.pth` | 综合最好的权重 |
| `checkpoint_best_regular.pth` | 未做平滑的最好权重 |

`resume` 为文件时，run 目录取该文件的父目录，并把该文件交给续训。`resume` 为目录时，按 `last.ckpt`、`checkpoint_best_total.pth`、`checkpoint_best_ema.pth` 的顺序找第一个存在的文件。都没有则失败，不新开目录。

## 预训练权重

入口 `model_path` 非空时，用该本地文件初始化，不再下载该档自带权重。文件必须存在，且与 `size` 是同一档。空字符串则仍用该档自带权重。

## 评估清单与 test 画框

公共 `val_classes` 只作用于 test。未写、`null` 或 `[]` 时等于准备结果里的 `train_classes`。非空时每一项都必须出现在该类别表里。训练和早停仍按全部训练类；画框和 `vis/predictions.jsonl` 里的计数丢掉不在清单中的类。

`save_vis=true` 且 `images/test` 有图时，训练结束用该 run 的 `checkpoint_best_total.pth`（没有则 `checkpoint_best_ema.pth`、`checkpoint_best_regular.pth`）对 test 画框，写到**该次 run 目录**的 `vis/`（`predictions.jsonl`、`vis_summary.json` 和画框图）。`predictions.jsonl` 的预测带 `match` 和 `iou`。同一套匹配（`vis_conf` 且同类 IoU ≥ `vis_iou`）同时写到该次 run 根目录的 `test_summary.json`，`vis/vis_summary.json` 与它相同。字段含总 `tp` / `fp` / `fn`、`precision`（tp/(tp+fp)）、`recall`（tp/(tp+fn)）、`images`、`images_with_gt`、`images_hit`（评估类真值至少中一条），以及 `per_class` 里每一类的框计数、`images`（有该类真值的图）和 `images_hit`。画框循环抛错时仍写出截至当前的这份文件，再把异常抛出。运行库能评估 test 划分时，同目录再写 `test_metrics.json`；评估失败只打日志，不代替 `test_summary.json`。`test_mark.py` 强制 `test_only`：已有 `data.yaml` 时不重新划分。权重大小顺序为 `resume` 中的 `.pth`、`output_dir` 下最新 run 的 best 权重、`model_path`。权重落在某次 run 目录时，画框写到该目录的 `vis/`；权重在 `output_dir` 之外时，写到 `output_dir/vis/`。

画框：预测对上真值为绿，多出来的预测为红，漏掉的真值为橙。框旁写类名；预测再写置信度。先画框再写字。标签矩形相交时，后一条先下移到上一条下方，下方放不下再右移。`vis_conf` 默认 0.5，`vis_iou` 默认 0.5，只影响这批图和 `test_summary.json` / `vis_summary.json`。

同一次 test 画框统计每次 `predict` 的时延（不含读图、画框和写文件）。CUDA 可用时计时前后同步。调用多于一次时第一次不计入。`vis_summary.json` 增加 `latency`：`scope=predict`、`batch=1`，以及每张图毫秒的 `mean_ms` / `p50_ms` / `p95_ms` / `min_ms` / `max_ms`。日志另打一行。`save_vis=false` 时不画框，也不另跑推理计时。

## 日志脱敏

训练期间，标准输出、标准错误和已挂上的日志处理器会把上游包名、带连字符的产品名及其大小写变体替换成 `mark`。缺库、规格不存在、续训文件缺失这几类入口自己抛出的错误，正文也不带这些名称。第三方库traceback 里的安装路径仍可能出现包目录名，本版不改写调用栈。

## 约束与边界

- 不引用 scanly 以外工程目录的训练模块。
- 不写回 `样本数据/` 与 VOC 源。
- 运行库写入 `scanly/train/requirements.txt`，与训练环境一起安装。入口脚本、配置注释和日志仍不写上游名称。
- 不改 YOLO / 检测 core / OBB 的入口行为。
- 不做 OBB、分割，不导出 ONNX，不接入 `tools/convert_2_onnx.py` 与现有推理服务。
- test 画框写在该次 run 目录的 `vis/`（权重不在 run 目录时写 `output_dir/vis/`），不改训练标签。训练过程中的早停仍按全部训练类。
