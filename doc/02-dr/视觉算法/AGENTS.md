# 视觉算法设计子目录

## 目录用途

承载板材封边缺陷检测的视觉算法架构、流水线与软件融合设计，服务算法实现与边端接入。

## 文档范围

**允许放入：**

- 视觉算法整体架构（如 V2）
- 检测/度量/融合/判定等子模块设计
- 与汇萃边端、视觉中心、PLC 结果契约的接口说明

**不应放入：**

- 训练样本统计与标注格式细则（见 `doc/00-客户资料/sample-format.md` 与 `defects/`）
- 纯硬件 BOM 原文（见客户资料物料清单）

## 编辑规则

- 主架构文档命名：`视觉算法架构V{n}.md`
- 对外客户简版命名：`视觉算法架构V{n}-客户简版.md`（只写设计结果，不含分析论证）
- 面扫/配方子模块：`01.面扫材质色系识别与配方适配.md`（与 01-or / 03-tr 同主题）
- 对外 Word 说明书：
  - V2：`板材封边缺陷视觉算法架构说明书V2.docx`（`defects/tools/gen_arch_docx_v2.py`，图件 `figures/`）
  - **V3**：`板材封边缺陷视觉算法架构说明书V3.docx`（`defects/tools/gen_arch_docx_v3.py`，图件 `figures_v3/`）
    - 相对 V2：**合入 2 面扫配方冷路径**；**推理环境固定 Windows IoT**
- 图件命名：`fig1_…` …；V3 另含 `fig7_area_recipe_flow.png`；改架构时同步重跑对应生成脚本
- 子模块设计可另建：`编号.主题.md`
- 修改架构时同步检查缺陷类别映射、接口字段与性能预算是否一致；若改设计结论，须同步更新客户简版与 Word 说明书；**改面扫/配方/运行环境时同步 V3 生成脚本与 docx**

## 协作约定

- 上游输入：`doc/00-客户资料/` 白皮书、软件设计说明书、物料清单、需求分析、图像处理笔记；`doc/01-or/` 面扫等 OR
- 下游实现：边端推理服务第一版见 `defects/predict/`（HTTP + Gradio，接口 `doc/02-dr/缺陷推理/`）；面扫识别与配方装载、模型训练与 `defects/tools/convert.py` 数据管线。**运行环境以现场为准**（架构 V3 曾固定 Windows IoT）。
- 与现有软件融合时，以「不改 MES/PLC/视觉中心协议」为默认约束
- 测试设计：`doc/03-tr/视觉算法/`
- 对外交付 Word 以 **V3** 为准；V2 文档保留作基线对照
