# 口径（先读）

不同版本的 **mAP 不能直接比绝对值**，原因叠加：

| 差异 | 涉及版本 |
|:---|:---|
| 任务 | v1.1–v1.3 为 **OBB**；v1.5、v2.1 为轴对齐 **detect** |
| 类别数 / 是否单类 | 6 / 18 / 19 / 单类 `item` / 4 类 |
| 相机 | 仅 cam2 → cam1+2+3 → 再拆回 cam2 |
| 输入边长 | 640 vs 1024 |
| 骨干 | YOLO11s / m / l |
| 划分 | 早期无独立 test；v1.5 起才有 test 日志 |

下文「最佳」指该 run 内 `metrics/mAP50-95(B)` 最高的 epoch。混淆矩阵为训练结束时 val 图，置信度阈值与 mAP 曲线（0.001）不同，只看相对漏检/误报结构。

# 结论摘要

1. **OBB 线（v1.2 / v1.3）**：胶类（开胶、胶缝、夹胶、残胶、崩缺）val 对角很高；**封边带损伤 / 过低 / 过高** 长期漏到 background。v1.3 已导出加密 ONNX，是现网推理用过的权重。
2. **v1.5**：全相机、YOLO11l、1024、150 epoch。训练目录混淆矩阵是单类 `item`（`single_cls=True`）。独立 `v1.5.test.log` 是另一次 **19 类** test（run 名 `cam-all-0901`），不能当成同一份权重的 test。
3. **v2.1（今日）**：按当前 `train.py` 只训 cam2 四类。**短带很好，过高全漏，损伤/过低召回不够，背景误报大量进损伤。** 不宜用它的 mAP 去和 v1.5 比高低。
4. **下一步优先**：v2.1 配方里拿掉 `Above`（方案本就默认关闭、样本极少）；损伤/过低加样本或单独阈值，而不是再堆 epoch。

# 各版本

## v1.1-cam2-0818-obb

首次 cam2 OBB。约 2.2 s/epoch，样本极少。

- val 曲线抖：P 在 0.3–0.87 间跳，典型小验证集。
- 混淆：`Scratch` 全无预测；`BandBroken2` 一半判成 `Below`；`Below` 一半漏检。
- ep100 相对 ep90：P 升到 0.86、R 掉到 0.49，过拟合开始。

**不能当产线模型。** 只证明 cam2 六类能跑通 OBB。

## v1.2-cam-0820-obb

合并 cam1/2/3（`cam123-0820`），仍是 s 档。这是 OBB 线上 **val mAP50-95 最高** 的一次（0.724）。

胶类对角 ≥0.92：`Bumps` / `ClampGlue` / `GlueGap` / `GlueResidue` / `GlueSeam` / `Scrape` / `Tackless`。  
`Hole` / `Label` / `Longer2` 为 1.00，框太少，指标虚高。

短板与后来各版同一族：

| 真值 | 对角 | 漏到 background |
|:---|---:|---:|
| BandBroken | 0.55 | 0.36 |
| BandBroken2 | 0.50 | 0.50 |
| Below | 0.55 | 0.36 |
| Scratch | 0 | （无预测） |
| Zigzag | 0.75 | 0.25 |

背景误报：`ResidualTape` 0.31、`GlueSeam` 0.20、`Tackless` 0.12。残带是屏蔽非缺陷，训练保留合理，但会占掉大量 FP。

## v1.3-cam-all-middle

骨干升到 **yolo11m-obb**，epoch 200，并纳入 `Above`。导出：

- `v1.3-onnx/`：加密 FP32
- `v1.3-onnx-fp16/`：FP16 ONNX（`imgsz=640`，19 类名写在 meta.json）

相对 v1.2：mAP50-95 **0.724 → 0.710**，不是变强。主因是 **Above 在混淆矩阵上 100% 漏检**，等权平均被拉穿；胶类仍然很好（`Tackless`/`Zigzag` 对角 1.00）。`BandBroken`/`Below` 仍约一半漏到 background。

训练后期 train/cls 降到 0.205，val/cls 仍约 0.43，m 档在 200 epoch 上已偏拟合。`patience=30` 几乎在 ep175 后该停。

边端性能（既有日志，CUDA ORT 1.18.1）：FP16 相对 FP32，`session.run` 约 1.31×，e2e 几乎打平（letterbox/NMS 占大头）。

## v1.5-cam-all

全量 `cam-all`、**检测框**、YOLO11l、1024。目录 **没有 `args.yaml`**。证据链：

- `results.csv` 无 `angle_loss` → detect
- 根目录权重名 `v1.5-cam-all-l1024.pt` → l + 1024
- 归一化混淆矩阵只有 `item` / `background` → **`single_cls=True`**
- 计数：TP=2217，FN=407，FP=572（约 R=0.84、P=0.80，与 csv 最佳 R=0.793 / P=0.826 同一量级）

曲线健康：mAP50-95 一直爬到 ep145；val/dfl 约 ep100 后略升，定位开始过拟合，但 mAP 仍微涨。150 epoch 偏短，不是早停。

**不要把 `v1.5.test.log` 当成这个 run 的 test。** 该日志是 `test.py` 对 `runs/cam-all-0901/weights/best.pt`、划分 `cam-all-0901-train` **test**（709 图 / 1308 框）的 **19 类** 结果，`SINGLE_CLS=False`：

| 范围 | P | R | mAP50 | mAP50-95 |
|:---|---:|---:|---:|---:|
| all | 0.812 | 0.716 | 0.746 | 0.534 |

test 上仍然弱的：`Above` R=0.282，`Zigzag` R=0，`BandBroken2` R=0.471，`BandBroken` R=0.659。仍强的：`Shorter` 0.942、`ClampGlue` 0.945、`Tackless` 0.880、`Hole`/`Label` 虚高。test 集未出现 `Scratch` 行（全库仅 3 框，可能全在 train/val）。

0901 抽检已说明 GlueGap/残胶、Below/胶缝等标错会直接打穿这些类——训练指标好不代表现场类名对。

# 跨版本短板（稳定出现）

无论 OBB 还是 detect、全相机还是 cam2：

1. **`Above`**：纳入即 100% 或接近全漏。设计已写「默认不训练」。v2.1 不应再放进 `TRAIN_CLASSES`。
2. **`BandBroken` / `BandBroken2` / `Below`**：中相机侧面目标，长期漏检；v2.1 损伤还把背景吃进来。
3. **`Scratch`**：样本极少，各版都学不会。
4. **胶类 vs 中相机类**：v1.2/v1.3 已经证明胶类可学；和损伤/高低混在一个等权 mAP 里会掩盖问题。分相机训练（v2.1 方向）是对的，但四类集合需要再收。

# 建议

| 用途 | 建议权重 | 不要用 |
|:---|:---|:---|
| 现网 OBB / Go ONNX | v1.3（已有加密 FP32/FP16） | v1.1 |
| 全相机「有没有框」（单类） | v1.5 训练目录这套 `item` | 拿它的 mAP 和 v2.1 比 |
| 中相机短带 | v2.1 | 指望它同时解决过高 |
| 中相机损伤 / 过低 | 现有权重都不够 | 只加 epoch |

v2.1 下一轮最小改动：`TRAIN_CLASSES` 改为 `BandBroken` / `Below` / `Shorter`（去掉 Above），同一 VOC 再训，看 R 和损伤 FP 是否一起改善。胶类、开胶仍走 cam1/3 或全相机多类，不要塞进这套四类。
